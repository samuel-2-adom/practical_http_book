Query Parameters

Query parameters let you filter, search, sort, and paginate data from an API — all without changing the URL path. This chapter explores every dimension of using them.

🎯 What you'll learn
  • How query parameters work in depth
  • Multiple parameters, optional vs required
  • Filtering, sorting, and pagination patterns
  • How to inspect the final URL that was built

8.1 Recap — What Query Parameters Do

Query parameters appear after the ? in a URL. They don't identify which resource you want — they modify how you want it:

/posts                 → all posts
/posts?userId=1        → posts by user 1
/posts?userId=1&_limit=5  → first 5 posts by user 1

8.2 Passing Multiple Parameters

Simply add more keys to your params dictionary:

import requests

params = {
    "userId": 1,
    "_limit": 5,
    "_sort": "id",
    "_order": "desc",
}

response = requests.get(
    "https://jsonplaceholder.typicode.com/posts",
    params=params
)

print(response.url)
# https://jsonplaceholder.typicode.com/posts?userId=1&_limit=5&_sort=id&_order=desc

8.3 Required vs Optional Parameters

API documentation will tell you which parameters are required and which are optional. Required parameters must be included or you'll get a 400 or 422 error. Optional parameters have defaults.

Example from a hypothetical weather API:

# Required
params = {
    "q": "Accra",        # REQUIRED: city name
    "appid": "YOUR_KEY",  # REQUIRED: API key
    "units": "metric",    # optional: default is Kelvin
    "lang": "en",         # optional: default is "en"
}

8.4 Building Parameters Dynamically

In real programs, parameters often come from user input or program logic:

def search_posts(user_id=None, limit=10, sort="id"):
    params = {
        "_limit": limit,
        "_sort": sort,
    }
    # Only add userId if it was provided
    if user_id is not None:
        params["userId"] = user_id

    response = requests.get(
        "https://jsonplaceholder.typicode.com/posts",
        params=params
    )
    return response.json() if response.ok else []

8.5 Common API Parameter Patterns

Most APIs follow recognisable patterns. Once you see one, you'll recognise them all:

# Search / filter
params = {"q": "python", "type": "repo"}

# Sorting
params = {"sort": "created_at", "order": "desc"}

# Pagination
params = {"page": 2, "per_page": 25}

# Date range
params = {"from": "2024-01-01", "to": "2024-12-31"}
📝 Exercises
Exercise 1 — What does response.url show you?
  • A The URL you passed to requests.get()
  • B Only the base URL, not the parameters
  • C The complete final URL including encoded parameters
response.url shows the full URL as it was actually sent — with all query parameters encoded and appended. This is useful for debugging what was actually requested.
Exercise 2 — You call requests.get(url, params={"city": "New York"}). How does requests handle the space in "New York"?
  • A It raises an error because spaces aren't allowed
  • B It URL-encodes it automatically (New+York or New%20York)
  • C It keeps the space as-is
The library automatically URL-encodes values. "New York" becomes "New+York" or "New%20York" in the URL. This is one of the main reasons to use params= rather than manually building the query string.
🧠 Mini-Project: Configurable Post Fetcher

Write a function fetch_posts(user_id=None, limit=10) that fetches posts from JSONPlaceholder. If user_id is given, filter by it. Print each post title. Call it a few ways to test it.

import requests

def fetch_posts(user_id=None, limit=10):
    params = {"_limit": limit}
    if user_id is not None:
        params["userId"] = user_id

    response = requests.get(
        "https://jsonplaceholder.typicode.com/posts",
        params=params
    )
    posts = response.json()
    for post in posts:
        print(f"[{post['id']}] {post['title']}")

fetch_posts()            # first 10 posts
fetch_posts(user_id=2)  # user 2's posts (up to 10)
fetch_posts(limit=3)    # just 3 posts
