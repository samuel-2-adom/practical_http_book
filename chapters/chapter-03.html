HTTP Methods

Every HTTP request has a method — a word that says what kind of action you want to perform. Understanding methods is what makes API documentation suddenly readable.

🎯 What you'll learn
  • What HTTP methods are and why they exist
  • The four methods you'll use constantly: GET, POST, PUT/PATCH, DELETE
  • How methods map to CRUD operations
  • Which Python function corresponds to which method

3.1 Why Methods Exist

Imagine you go to a library. You might want to:

  • · Look up a book
  • · Add a new book to the collection
  • · Update the information about a book
  • · Remove a book from the collection

These are fundamentally different operations. HTTP methods are how you tell the server which type of operation you want to perform — using the same URL but a different "verb".

3.2 The Four Main Methods

GET — Retrieve something

GET requests information from the server. It doesn't change anything. It just asks: "Give me this."

GET /users/42

"Give me the data for user 42."

GET /products?category=books

"Give me all products in the books category."

🔵 GET is safe and idempotent

Safe means it doesn't change anything on the server. Idempotent means doing it ten times has the same result as doing it once. You can GET the same URL a hundred times without side effects. This is why browsers cache GET requests.

POST — Create something new

POST sends data to the server to create a new resource.

POST /users
Body: {"name": "Samuel", "email": "s@example.com"}

"Create a new user with this data."

Notice POST usually has a body — data sent along with the request. GET requests typically don't have a body; POST requests usually do.

PUT / PATCH — Update something

Both methods update existing data, but with a subtle difference:

  • · PUT — replace the entire resource with new data
  • · PATCH — update only the fields you specify
PUT /users/42
Body: {"name": "Sam", "email": "sam@example.com", "city": "Accra"}
# Replaces the entire user record

PATCH /users/42
Body: {"city": "Kumasi"}
# Only updates the city field

In practice, many APIs only implement one of these. PATCH is increasingly preferred.

DELETE — Remove something

DELETE tells the server to remove the specified resource.

DELETE /users/42

"Delete user 42."

3.3 CRUD and HTTP Methods

You may have heard of CRUD — Create, Read, Update, Delete. These four operations map directly onto HTTP methods:

CRUD Operation HTTP Method requests function ───────────────────────────────────────────────── Create POST requests.post() Read GET requests.get() Update PUT / PATCH requests.put() / requests.patch() Delete DELETE requests.delete()

This mapping is at the heart of REST APIs, which we'll cover properly in Chapter 12. For now, just notice the pattern: the method tells the server what kind of thing you want to do, and the URL tells it what you want to do it to.

3.4 Methods You'll Use Less Often

There are other HTTP methods, but you'll rarely need them when working with typical APIs:

  • · HEAD — like GET, but returns only headers, no body (useful for checking if a resource exists)
  • · OPTIONS — asks what methods the server allows for a URL
💡 Don't memorize these

Know that HEAD and OPTIONS exist. Look them up if you ever need them. For 90% of API work, you'll only use GET, POST, PUT/PATCH, and DELETE.

3.5 Reading API Docs — Methods in the Wild

When you look at API documentation, the method is always listed first. For example, GitHub's API documentation might show:

GET /repos/{owner}/{repo}/issues List issues POST /repos/{owner}/{repo}/issues Create an issue PATCH /repos/{owner}/{repo}/issues/{n} Update an issue DELETE /repos/{owner}/{repo}/issues/{n} Delete an issue

Same URL pattern, different method — completely different operation. This is the pattern you'll see across virtually every modern API.

📝 Exercises
Exercise 1 — You want to retrieve a list of blog posts. Which method?
  • A GET
  • B POST
  • C DELETE
GET — you're reading/retrieving data, not creating or modifying anything. In Python: requests.get("/posts").
Exercise 2 — You want to create a new comment on a post. Which method?
  • A GET
  • B POST
  • C PATCH
POST — you're creating a new resource. In Python: requests.post("/posts/5/comments", json={"text": "Great post!"}).
Exercise 3 — You want to change just the title of an existing blog post. Which method is most appropriate?
  • A PUT
  • B POST
  • C PATCH
PATCH — you're updating only one field (the title), not replacing the entire post. PUT would require you to send the complete post data to replace it wholesale. PATCH is for partial updates.
Exercise 4 — Which HTTP method is "safe" — meaning it doesn't modify server data?
  • A GET
  • B POST
  • C DELETE
GET — it only retrieves. POST creates, DELETE removes, PATCH/PUT modify. You can call GET any number of times and the server state won't change.
🧠 Checkpoint

Without looking back: map each CRUD operation to its HTTP method and the Python requests function.

📌 What to remember

· GET — read, retrieve, fetch (no body, safe)

· POST — create (has a body)

· PUT/PATCH — update (PUT replaces all, PATCH updates part)

· DELETE — remove

The method + URL together define the operation.
