URLs

You've typed URLs thousands of times. Now you'll actually understand what each part means — and why that matters when you're writing code that talks to APIs.

🎯 What you'll learn
  • Every component of a URL and what it does
  • What query parameters are and how they work
  • What URL encoding is
  • How to read an API URL and understand it immediately

2.1 A URL Is an Address

A URL — Uniform Resource Locator — is the address of a resource on the web. That resource might be a webpage, an image, a JSON file, a video, or an API endpoint.

Every URL points to exactly one thing. When your Python program makes a request, it needs to know precisely where to send that request. That's the URL's job.

2.2 Anatomy of a URL

Take this URL apart:

https://api.example.com:443/users/42?sort=asc&limit=10#profile
https://api.example.com:443/users/42?sort=asc&limit=10#profile │ │ │ │ │ │ │ │ │ │ │ └── fragment │ │ │ │ └─────────────── query string │ │ │ └──────────────────────── path │ │ └──────────────────────────── port │ └──────────────────────────────────────────── host / domain └──────────────────────────────────────────────────── scheme

Let's go through each part.

2.3 Scheme (Protocol)

The scheme tells the browser (or Python) how to communicate. It comes before the ://.

https://example.com
│
└── scheme: "https"

Common schemes you'll see:

  • · http — plain HTTP (unencrypted)
  • · https — HTTP + TLS encryption (what you should always use)
  • · ftp — file transfer (rare in modern APIs)
⚠️ Always use https://

When calling APIs, always use https://. Plain http:// sends everything unencrypted — including your API keys and tokens. The requests library will follow HTTPS by default.

2.4 Host (Domain)

The host tells the client which computer to connect to.

https://api.example.com/users
        │
        └── host: "api.example.com"

You'll often see APIs using a subdomain like api. to separate the API from the main website:

api.github.com       ← GitHub's API
api.openweathermap.org  ← OpenWeather API
api.spotify.com      ← Spotify API

2.5 Port

The port is a number that specifies which "channel" on the server to connect to. Most of the time you don't see it because the default ports are assumed:

  • · HTTP defaults to port 80
  • · HTTPS defaults to port 443

When you do see a port, it's explicit:

http://localhost:8000/api/users
                 │
                 └── port 8000 (a local development server)

You'll often use explicit ports when running APIs locally during development.

2.6 Path

The path identifies the specific resource you want on the server. It comes after the host and always starts with /.

https://api.example.com/users/42/posts
                        │
                        └── path: "/users/42/posts"

In an API, paths usually map to resources:

/users          → all users
/users/42       → user with ID 42
/users/42/posts → posts by user 42
/products       → all products
/products/7     → product with ID 7

The number 42 in /users/42 is called a path parameter — it's part of the URL path itself, identifying a specific resource. We'll come back to this in Chapter 8.

2.7 Query String

The query string comes after a ? and contains key-value pairs separated by &.

https://api.example.com/search?q=python&sort=stars&page=2
                               │
                               └── query string starts here

Key-value pairs:
  q     = "python"
  sort  = "stars"
  page  = "2"

Query parameters are used to filter, sort, search, or configure what the server returns. They don't identify a resource — they modify or narrow the request.

🔵 Path vs Query — the key distinction

Path parameters identify which resource you want: /users/42 — give me user 42 specifically.

Query parameters modify how you want it: /users?sort=name&limit=10 — give me users, sorted by name, ten at a time.

2.8 Fragment

The fragment comes after # and refers to a section within the page.

https://docs.example.com/guide#authentication
                               │
                               └── jump to the "authentication" section

Fragments are processed by the browser — they're never sent to the server. For APIs, you'll almost never use fragments, so don't worry about them much.

2.9 URL Encoding

URLs can only contain certain characters. Spaces, special characters, and non-ASCII text must be encoded — replaced with a % followed by a hex code.

Space   →  %20
#       →  %23
&       →  %26
=       →  %3D
?       →  %3F

For example, if you're searching for "hello world", the URL becomes:

https://api.example.com/search?q=hello%20world
💡 Good news

The requests library handles URL encoding automatically. You pass a Python dictionary and it builds the correctly-encoded URL. You rarely need to encode manually — but you should understand what you're seeing when a URL contains %20 or similar.

2.10 Reading API URLs

Let's practice reading real API URLs you'll encounter:

https://api.github.com/repos/python/cpython/issues?state=open&per_page=30
Scheme: https Host: api.github.com Path: /repos/python/cpython/issues │ │ │ │ │ │ │ └── resource: issues │ │ └────────── repo name: cpython │ └────────────────── owner: python └───────────────────────── resource type: repos Query: state=open (only open issues) per_page=30 (30 results per page)
https://api.openweathermap.org/data/2.5/weather?q=Accra&units=metric&appid=KEY
Scheme: https Host: api.openweathermap.org Path: /data/2.5/weather Query: q=Accra (city name) units=metric (Celsius, not Fahrenheit) appid=KEY (your API key)

Reading URLs like this — breaking them into their components — is a skill you'll use constantly when working with APIs.

Practice Questions

📝 Exercises
Exercise 1 — In the URL https://api.example.com/products?category=books, what is the query parameter?
  • A /products
  • B api.example.com
  • C category=books
Everything after the ? is the query string. Here it's category=books — a key of category with value books. The path is /products and the host is api.example.com.
Exercise 2 — What does the ? character separate?
  • A The scheme from the host
  • B The path from the query string
  • C Two query parameters from each other
The ? marks where the path ends and the query string begins. The & character separates individual query parameters from each other. The :// separates the scheme from the host.
Exercise 3 — You want to request user #99 from an API. Which URL structure is most typical?
  • A /users/99
  • B /users?id=99
  • C Both are equally common
Both patterns exist in the wild, but REST APIs (the most common style) typically use path parameters to identify specific resources: /users/99. Query parameters like ?id=99 are more often used for filtering or searching.
Exercise 4 — Why does https://api.example.com not need to include :443?
  • A Because HTTPS doesn't use ports
  • B Because 443 is the default HTTPS port, so it's implied
  • C Because the port is always random
Port 443 is the default for HTTPS and port 80 is the default for HTTP. When you use the default, you can omit it. Ports only appear explicitly when something non-standard is being used — common in local development.

Identify the Parts

Break this URL into its components — try it without hints first:

https://api.spotify.com/v1/search?q=jazz&type=track&limit=5
Scheme:  https
Host:    api.spotify.com
Path:    /v1/search       (v1 = API version 1)
Query:
  q      = "jazz"         (search term)
  type   = "track"        (what kind of result)
  limit  = "5"            (maximum results to return)
🧠 Checkpoint

Without looking back, write down what each symbol does in a URL: ://   /   ?   =   &   #

📌 What to remember from this chapter

scheme://host:port/path?key=value&key2=value2#fragment

· Scheme — how to connect (https)

· Host — which server

· Path — which resource

· Query string — modify/filter the request

· requests handles URL encoding automatically
