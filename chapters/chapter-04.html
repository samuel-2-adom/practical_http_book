Status Codes

Every response from a server includes a three-digit number. That number tells you immediately whether things went well, and if not, whose fault it is.

🎯 What you'll learn
  • What status codes are and how to read them
  • The five categories of status codes
  • The specific codes you'll encounter constantly
  • How to distinguish client errors from server errors

4.1 What Is a Status Code?

Every HTTP response starts with a status code — a three-digit number that summarises the result of the request. The first digit tells you the category; the full number tells you the specifics.

Client → request → Server Client ← response ← Server Response includes: Status line: HTTP/1.1 200 OK │ │ │ └── human-readable phrase └────── status code Headers: ... Body: ... (the data you asked for)

4.2 The Five Categories

1xx — Informational (rarely seen in practice) 2xx — Success ✅ the request worked 3xx — Redirection ↩️ go somewhere else 4xx — Client error ❌ you sent something wrong 5xx — Server error 🔥 the server had a problem
🔵 The most important distinction

4xx errors are your fault — your request was wrong, unauthorized, or asking for something that doesn't exist.

5xx errors are the server's fault — the server crashed, is overloaded, or has a bug. Not your problem to fix.

4.3 Success Codes (2xx)

200 OK

The most common success code. Everything worked exactly as expected.

# Typical response to a GET request
HTTP/1.1 200 OK
# Body contains the requested data

201 Created

The request succeeded and a new resource was created. Typically returned after a successful POST.

# Typical response after creating a resource
POST /users → 201 Created
# The new user now exists on the server

204 No Content

Success, but there's nothing to return. Common after a DELETE or a PATCH that doesn't need to return data.

DELETE /users/42 → 204 No Content
# User 42 is gone. Nothing to send back.

4.4 Redirect Codes (3xx)

301 Moved Permanently

The resource has moved to a new URL permanently. The requests library follows redirects automatically, so you'll rarely need to handle these manually.

302 Found (Temporary Redirect)

Temporarily redirected to another URL. Again, requests handles this for you by default.

💡 Redirects are automatic

By default, requests follows redirects automatically. If a URL moves, you'll get the final response without having to do anything. You can disable this with allow_redirects=False if you ever need to inspect the redirect itself.

4.5 Client Error Codes (4xx) — Your fault

These are the ones you'll encounter most when developing. They mean something about your request was wrong.

400 Bad Request

The server couldn't understand your request. Usually means malformed JSON, missing required fields, or invalid parameter values.

POST /users
Body: {name: "Samuel"}  ← invalid JSON (missing quotes)
→ 400 Bad Request

401 Unauthorized

You need to authenticate but haven't. Either no credentials were sent, or they were invalid.

GET /private/data   ← no API key sent
→ 401 Unauthorized

403 Forbidden

You're authenticated, but you don't have permission for this action. The difference from 401: the server knows who you are, but says you can't do this.

# You're logged in, but trying to delete another user's post
DELETE /users/99/posts/5 → 403 Forbidden

404 Not Found

The resource doesn't exist. Either the URL is wrong or the thing you're asking for was deleted.

GET /users/9999 → 404 Not Found
# User 9999 doesn't exist

422 Unprocessable Entity

The request was understood (valid JSON, right format) but the data itself is invalid — like a user email that's already taken, or an age set to -5.

429 Too Many Requests

You've hit the API's rate limit — sent too many requests in a short period. Most APIs have a limit like "100 requests per minute". You'll need to wait before retrying.

429 Too Many Requests
Retry-After: 60   ← wait 60 seconds

4.6 Server Error Codes (5xx) — Their fault

500 Internal Server Error

Something crashed on the server. There's nothing wrong with your request — the server just failed. Try again later.

502 Bad Gateway

The server was acting as a proxy and got a bad response from another server upstream. Often temporary.

503 Service Unavailable

The server is temporarily unavailable — overloaded, down for maintenance, or having a problem. Try again later.

⚠️ Common mistake

Beginners often assume a 500 error means their Python code is broken. It doesn't — it means the server has a problem. Always check the status code before debugging your code. If it's 5xx, the bug isn't yours.

4.7 Checking Status Codes in Python

In Python, you access the status code like this (more detail in Chapter 7):

import requests

response = requests.get("https://api.example.com/users/42")

print(response.status_code)   # e.g. 200

if response.status_code == 200:
    print("Success!")
elif response.status_code == 404:
    print("Not found")
elif response.status_code >= 500:
    print("Server error — not our fault")
📝 Exercises
Exercise 1 — You send a GET request and get back status 200. What does this mean?
  • A The resource was created
  • B The request succeeded and the data was returned
  • C The server is unavailable
200 OK is the standard success response. The request worked and the response body contains what you asked for.
Exercise 2 — You get a 401. What should you check first?
  • A Whether the server is down
  • B Whether the URL path is correct
  • C Whether you've sent valid credentials/API key
401 means authentication failed. Check that you're sending your API key or token correctly — right header name, correct value, not expired.
Exercise 3 — A 503 error appears. Is this a bug in your code?
  • A No — it's a server-side problem
  • B Yes — check your request format
  • C It depends on what you sent
5xx errors are always server-side problems. Your request was fine — the server itself is unavailable or crashed. Try again later; there's nothing to fix in your code.
Exercise 4 — What's the difference between 401 and 403?
  • A 401 is a server error; 403 is a client error
  • B 401 means not authenticated; 403 means authenticated but not allowed
  • C They mean the same thing
401 = "Who are you? Prove it." (no valid credentials sent). 403 = "I know who you are, but you're not allowed to do this." (authenticated but unauthorized for this specific action).
