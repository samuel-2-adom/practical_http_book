Part I — Understanding the Web · Chapter 1

How the Web
Actually Works

Before writing a single line of requests code, you need a mental picture of what's happening. This chapter builds that picture.

🎯 What you'll learn
  • What a client is, and what a server is
  • What HTTP and HTTPS mean
  • What a request and a response are
  • What happens when you visit a website
  • How Python fits into all of this
  • The difference between a website and an API
💡 Reading tip

You don't need to memorize the definitions in this chapter. Understanding is the goal. The details will stick naturally as you write code in later chapters.

1.1 The Internet vs. the Web

People often use "the Internet" and "the Web" interchangeably, but they're not the same thing.

Think of the Internet as the underlying network — the cables, routers, and protocols that let computers communicate with each other at all.

The Web is one service that runs on top of that network — specifically, documents and data exchanged using HTTP.

But the Web isn't the only thing running on the Internet:

Internet
│
├── Web (HTTP/HTTPS)      ← what we're learning
├── Email (SMTP/IMAP)
├── SSH
├── Online games
├── File transfers (FTP)
└── Many other services

When we learn HTTP and APIs, we're learning about one specific language that computers use to talk to each other over the Internet.

1.2 Client and Server

These two words appear everywhere in web development. They have specific meanings.

Client

A client is anything that asks a server for something. For example:

  • · Chrome or Firefox
  • · Your phone
  • · A Python program

Server

A server is a computer or program that receives requests and sends something back in response.

When you visit https://example.com, your browser is the client. The computer running example.com is the server.

CLIENT SERVER Browser │ │ "Give me this page" │ └──────────────────────────────► │ │ ◄──────────────────────────────┘ "Here is the page"
🔵 Key idea

Every web interaction is a client sending a request and a server sending a response. Keep this model in your head — it underpins everything else in this book.

1.3 A Python Program Can Be a Client

This is where things get interesting for us.

A browser isn't the only thing that can communicate with a server. Python can do it too. Instead of a browser making a request, we can write code that does it:

import requests

response = requests.get("https://example.com")

At a high level, this means:

Python program │ │ HTTP request ▼ Server │ │ HTTP response ▼ Python program

That's the fundamental idea behind this entire book. Python sends a request; a server sends something back; Python uses that response.

1.4 What Is a Request?

A request is a message from a client to a server that says: "I want something."

For example, a client might send:

GET /products

"Give me the list of products."

GET /weather

"Give me the current weather."

POST /users

"Here is data. Create a new user with it."

We'll explore all the different types of requests in Chapter 3. For now, remember:

🔵 Request

A message sent to the server by the client.

1.5 What Is a Response?

After receiving a request, the server sends something back. That's the response.

Client │ │ Request → ▼ Server │ │ Response ← ▼ Client

A response might contain:

  • · HTML (a webpage)
  • · JSON (structured data)
  • · Plain text
  • · Images or files
  • · An error message

When you visit a website, the response usually contains HTML. When you call an API, the response usually contains JSON. That distinction is very important — we'll come back to it in section 1.9.

1.6 What Happens When You Visit a Website?

Suppose you type https://example.com into your browser. A simplified version of what happens:

You │ │ type URL into browser ▼ Browser │ │ sends HTTP request ▼ Server │ │ sends HTTP response (HTML) ▼ Browser │ │ renders the HTML ▼ Web page appears

The actual process involves more steps — DNS lookups, TCP connections, TLS handshakes — but those are network engineering details we don't need right now.

💡 Note

We don't need to become network engineers to use the requests library. The library handles all of that for us. Our job is understanding what requests and responses mean.

1.7 Where Does HTTP Come In?

You might be thinking: how does the client and server know what format these messages should use? That's where HTTP comes in.

HTTP stands for Hypertext Transfer Protocol. It's a set of rules that defines:

  • · How requests are structured
  • · How responses are structured
  • · What different types of requests mean
  • · How errors are reported

Think of it as a shared language that clients and servers use to communicate.

Python │ │ HTTP request ▼ Server │ │ HTTP response ▼ Python

1.8 HTTPS

Most websites use https:// rather than http://. The S stands for Secure.

HTTPS is HTTP protected using TLS encryption. The practical difference:

Plain HTTP Client ─────────────────────────── Server data travels readable (anyone watching can see it) HTTPS Client ═════════════════════════════ Server data is encrypted in transit (unreadable to observers)

This matters especially for passwords, API keys, tokens, and any personal data. When you use requests, you'll almost always use https:// URLs, and the library handles the encryption automatically.

🔵 HTTPS = HTTP + TLS encryption

You don't need to understand TLS internals. Just know that HTTPS keeps the communication private between client and server.

1.9 Website vs. API

This is one of the most important distinctions in this book.

Suppose you visit https://example.com. The server might return:

<h1>Welcome to Example!</h1>
<p>This is a webpage.</p>

Your browser takes that HTML and renders it as a visual page.

But an API might return:

{
    "name": "Samuel",
    "city": "Accra",
    "temperature": 28
}

That's not intended for a human to read visually. It's data intended for a program to use.

Website API Server Server ↓ ↓ HTML JSON ↓ ↓ Browser Python program ↓ ↓ Visual page Your code uses the data

This is a useful mental model. In practice there are exceptions, but this captures the key distinction: a website serves humans; an API serves programs.

1.10 The Big Picture

Here's everything from this chapter put together:

INTERNET │ ┌────────────┴────────────┐ │ │ CLIENT SERVER │ │ Browser / Python Web application │ │ │ HTTP/HTTPS │ │ │ ├──────── REQUEST ────────► │ │ ◄──────── RESPONSE ───────┤ │ ▼ Use the returned data

When we're working with an API specifically, the flow looks like this:

Python program │ │ HTTP request ▼ API endpoint (server) │ │ HTTP response ▼ JSON data │ ▼ Python dict / list │ ▼ Your program does something with it

That's the core idea behind everything we're about to learn.

Practice Questions

Imagine you have a Python program that wants the current weather. It sends a request to https://api.example.com/weather, and the server responds with:

{
    "temperature": 28,
    "condition": "Sunny"
}
📝 Guided Practice
Question 1 — Who is the client in this scenario?
  • A The API server
  • B Your Python program
  • C The JSON response
The Python program is the client because it's the one making the request — asking the server for something. The server is on the receiving end, waiting for requests to come in.
Question 2 — What is the request?
  • A {"temperature": 28, "condition": "Sunny"}
  • B The message Python sends to the server
  • C The Python program itself
The request is the message sent to the server. The JSON is the response (what comes back). The Python program is the client, not the request itself.
Question 3 — What is the response?
  • A The information sent back by the server
  • B The URL
  • C Python's requests module
The response is what the server sends back to the client. In this case it's the JSON containing temperature and condition.
Question 4 — What is the API server sending back in this example?
  • A HTML
  • B JSON
  • C Python code
APIs typically respond with JSON — structured data that a program can read and work with. HTML is what websites return for browsers to render visually.
Question 5 — What does HTTPS provide that plain HTTP doesn't?
  • A Faster Python code
  • B Encrypted communication using TLS
  • C A different programming language
HTTPS is HTTP + TLS encryption. The data travelling between client and server is encrypted, so anyone observing the network can't simply read it.
