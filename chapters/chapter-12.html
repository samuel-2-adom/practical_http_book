What is a REST API?

You've been using REST APIs without knowing it. This chapter names the pattern, explains why it works, and teaches you to read any API documentation confidently.

🎯 What you'll learn
  • What REST is and why it matters
  • Resources, endpoints, and collections
  • How REST maps to the HTTP methods you already know
  • How to read unfamiliar API documentation

12.1 What Is REST?

REST stands for Representational State Transfer. Don't worry about the full name — what matters is what it describes: a style of designing APIs that uses HTTP in a predictable, consistent way.

A REST API organises everything around resources — things that exist: users, posts, orders, products. Each resource has its own URL, and you act on it using HTTP methods.

12.2 Resources and Endpoints

A resource is a "thing" in your system. An endpoint is the URL where you interact with that thing.

Resource: User ───────────────────────────────────────────── GET /users → list all users POST /users → create a new user GET /users/42 → get user 42 PUT /users/42 → replace user 42 PATCH /users/42 → update part of user 42 DELETE /users/42 → delete user 42

Notice: same URL, different method = different operation. This is the core REST pattern.

12.3 Collections and Items

/users          ← collection (plural noun)
/users/42       ← individual item (noun + id)
/users/42/posts ← nested collection (user 42's posts)

REST APIs are almost always nouns in the URL — never verbs. The HTTP method is the verb.

⚠️ Not REST (verbs in URL)

GET /getUser?id=42 — wrong, verb in URL

POST /createUser — wrong, action in URL

GET /users/42 + POST /users — right, nouns with HTTP method verbs

12.4 Reading API Documentation

When you find an unfamiliar API, ask these questions in order:

1. What is the base URL? → https://api.example.com/v1 2. What are the endpoints (resources)? → /users, /products, /orders 3. What HTTP method is required? → GET, POST, PATCH, DELETE 4. What parameters are required? → path params, query params, body 5. Does it require authentication? → API key, Bearer token, Basic auth 6. What does the response look like? → JSON structure, fields, types 7. What errors can occur? → 400 missing field, 401 bad key, 404 not found

12.5 API Versioning

You'll often see a version number in the URL:

https://api.example.com/v1/users
https://api.example.com/v2/users

APIs change over time. Versioning lets old code keep working while new features go into v2. Always check which version the docs are for.

📝 Exercises
Exercise 1 — What does "REST" describe?
  • A A programming language for APIs
  • B A style of designing APIs that uses HTTP predictably around resources
  • C A Python library
REST is an architectural style, not a protocol or library. It's a set of conventions for how to design HTTP APIs: use nouns in URLs, use HTTP methods as verbs, return meaningful status codes.
Exercise 2 — Which URL follows REST conventions to delete a post with ID 7?
  • A GET /deletePost?id=7
  • B POST /posts/delete/7
  • C DELETE /posts/7
REST uses the HTTP method as the action: DELETE /posts/7. URLs should be nouns identifying the resource; the method tells the server what to do with it.
