Working with JSON

JSON is the language APIs speak. You already know Python dicts and lists — JSON is just their text representation. This chapter makes that mapping completely explicit.

🎯 What you'll learn
  • What JSON is and why APIs use it
  • How JSON maps to Python types
  • Navigating nested JSON structures
  • Encoding Python data as JSON

13.1 What Is JSON?

JSON — JavaScript Object Notation — is the data format almost every modern API uses. It's a text format for representing structured data, and it looks a lot like Python dictionaries and lists:

{
    "name": "Samuel",
    "age": 25,
    "active": true,
    "score": null,
    "languages": ["Python", "JavaScript"],
    "address": {
        "city": "Accra",
        "country": "Ghana"
    }
}

13.2 JSON → Python Type Mapping

JSON type Python type Example ────────────────────────────────────────────── object dict {"key": "val"} array list [1, 2, 3] string str "hello" number (int) int 42 number (float) float 3.14 true True true false False false null None null

When you call response.json(), requests parses the JSON and returns native Python types. You don't need to do anything extra.

13.3 Navigating JSON Data

data = response.json()

# Top-level keys
print(data["name"])           # "Samuel"
print(data["age"])            # 25

# List access
print(data["languages"][0])  # "Python"

# Nested dict
print(data["address"]["city"])  # "Accra"

# Safe access with .get() — returns None instead of KeyError
print(data.get("phone"))      # None (key doesn't exist)
print(data.get("phone", "N/A"))  # "N/A" (default)

13.4 Looping Over JSON Arrays

# API returns a list of users
users = response.json()  # list of dicts

for user in users:
    print(f"{user['id']}: {user['name']} ({user['email']})")

# Filter in Python
active_users = [u for u in users if u.get("active")]

13.5 Encoding Python as JSON

Use the json module to convert Python to a JSON string:

import json

data = {"name": "Samuel", "score": 98}

# Python → JSON string
json_str = json.dumps(data)
print(json_str)   # '{"name": "Samuel", "score": 98}'

# Pretty-printed
print(json.dumps(data, indent=2))
💡 You rarely need json.dumps() with requests

When you use requests.post(url, json=data), the library calls json.dumps() for you. You only need the json module directly when saving to files or doing other non-requests work.

13.6 Handling Missing Keys Safely

# Risky — KeyError if "phone" doesn't exist
phone = user["phone"]

# Safe — returns None if missing
phone = user.get("phone")

# Safe with default
phone = user.get("phone", "not provided")

# Nested safe access
city = user.get("address", {}).get("city", "unknown")
📝 Exercises
Exercise 1 — A JSON response has {"results": [{"id": 1}, {"id": 2}]}. How do you get the first id?
  • A data["results"][0]["id"]
  • B data[0]["results"]["id"]
  • C data.results[0].id
data["results"] gives you the list. [0] gives the first item (a dict). ["id"] gives the id. Python uses square-bracket notation for both dict keys and list indices — never dot notation like JavaScript.
Exercise 2 — What Python type does a JSON null become?
  • A 0
  • B False
  • C None
JSON null → Python None. JSON true/false → Python True/False. These are the three non-obvious mappings to remember.
🧠 Mini-Project: JSON Explorer

Fetch https://jsonplaceholder.typicode.com/users and for each user print: their name, email, and the name of their company (it's nested under "company" → "name"). Use .get() for safety.

import requests

response = requests.get("https://jsonplaceholder.typicode.com/users")
users = response.json()

for user in users:
    name    = user.get("name", "?")
    email   = user.get("email", "?")
    company = user.get("company", {}).get("name", "?")
    print(f"{name} | {email} | {company}")
