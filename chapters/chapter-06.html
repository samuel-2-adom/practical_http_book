Installing Requests

Part I was theory. From here on, you write code. This chapter gets your environment ready and walks you through your very first real HTTP request in Python.

🎯 What you'll learn
  • How to install the requests library
  • The structure of the Response object
  • How to make your first GET request and read the result
  • How to inspect what the server actually sent back

6.1 Why Not Use the Standard Library?

Python's standard library includes urllib for making HTTP requests. It works, but it's verbose and tedious for everyday use:

# Using urllib — the standard library way
import urllib.request
import urllib.parse
import json

url = "https://api.example.com/users"
with urllib.request.urlopen(url) as response:
    data = json.loads(response.read().decode("utf-8"))
# Using requests — the same thing
import requests

data = requests.get("https://api.example.com/users").json()

requests is the de facto standard for HTTP in Python. It's more readable, more powerful, and handles edge cases automatically. Install it once and use it everywhere.

6.2 Installing Requests

In your terminal:

pip install requests

If you're using a virtual environment (recommended):

python -m venv venv
source venv/bin/activate   # Mac/Linux
venv\Scripts\activate      # Windows

pip install requests

Verify it installed correctly:

python -c "import requests; print(requests.__version__)"
# Should print something like: 2.31.0

6.3 Your First Request

Create a file called first_request.py and type this:

import requests

response = requests.get("https://httpbin.org/get")

print(response.status_code)
print(response.text)

Run it: python first_request.py

You should see a status code of 200 and a JSON response showing information about your own request. httpbin.org is a test service that echoes back what you sent.

💡 httpbin.org

httpbin.org is a free service perfect for learning. It has endpoints like /get, /post, /status/404 that let you test your code without needing a real API.

6.4 The Response Object

When you call requests.get(), you get back a Response object. It's not just the raw data — it contains everything the server sent:

response = requests.get("https://httpbin.org/get")

response.status_code   # 200  (integer)
response.text          # response body as a string
response.content       # response body as raw bytes
response.headers       # response headers (dict-like)
response.url           # the final URL (after any redirects)
response.json()        # parse body as JSON → Python dict/list

status_code

print(response.status_code)   # 200
print(type(response.status_code))  # <class 'int'>

text

The response body decoded as a Unicode string. Use this for HTML or when the response is text.

print(response.text)
# '{\n  "args": {}, \n  "headers": {...}, ...'

content

The raw bytes of the response. Use this for binary data like images or files.

print(response.content)
# b'{\n  "args": {}, ...'

json()

If the response is JSON, this parses it directly into a Python dictionary or list. This is what you'll use most often with APIs.

data = response.json()
print(type(data))  # <class 'dict'>
print(data["url"])  # 'https://httpbin.org/get'

6.5 Checking if a Request Succeeded

The simplest check:

response = requests.get("https://httpbin.org/get")

if response.status_code == 200:
    data = response.json()
    print("Got data:", data)
else:
    print(f"Something went wrong: {response.status_code}")

There's also a shortcut — the ok property returns True for any 2xx status code:

if response.ok:
    print("Success")
else:
    print(f"Error {response.status_code}")
⚠️ Don't assume success

Always check the status code before trying to use .json(). If you call .json() on an error response, you might get an exception if the body isn't valid JSON, or worse — silently process error data as if it were real data.

Exercise 1 — What does response.text return?
  • A A Python dictionary
  • B The response body as a string
  • C The status code as text
response.text is the response body decoded as a string. Use response.json() to parse JSON into a Python dict/list, or response.content for raw bytes.
Exercise 2 — What type does response.json() return for a JSON object response?
  • A str
  • B list
  • C dict
A JSON object {"key": "value"} becomes a Python dict. A JSON array [1, 2, 3] becomes a Python list. The type depends on what the server returned.
Exercise 3 — What does response.ok return for a 404 response?
  • A False
  • B True
  • C None
response.ok is True only for 2xx status codes (success). A 404 is a 4xx error, so ok returns False.

📌 What to remember

· Install once: pip install requests

· requests.get(url) → Response object

· response.status_code → integer

· response.ok → True for 2xx

· response.text → body as string

· response.json() → body parsed as Python dict/list

· response.headers → response headers

· Always check status code before using the data
