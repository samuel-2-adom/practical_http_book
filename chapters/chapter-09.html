POST Requests

GET retrieves. POST creates. This chapter teaches you how to send data to a server and handle what comes back.

🎯 What you'll learn
  • How to send data to a server with POST
  • The difference between form data and JSON
  • How to send JSON with requests.post()
  • Reading the response from a POST

9.1 POST vs GET

GET retrieves data. POST creates something new — and sends data to the server in the request body.

GET /posts → "give me posts" (no body) POST /posts → "create a post" + body containing the new post data

9.2 Sending JSON Data

Modern APIs almost always expect JSON in the request body. Use the json= parameter:

import requests

new_post = {
    "title": "My First Post",
    "body": "This is the content of my post.",
    "userId": 1,
}

response = requests.post(
    "https://jsonplaceholder.typicode.com/posts",
    json=new_post
)

print(response.status_code)   # 201 Created
print(response.json())        # returns the created post with an id
🔵 json= does two things automatically

When you use json=data, requests automatically:

1. Serializes your Python dict to a JSON string

2. Sets the Content-Type: application/json header

You don't have to do either manually.

9.3 Sending Form Data

Older APIs sometimes expect form-encoded data (like an HTML form submission). Use data= instead of json=:

response = requests.post(
    "https://httpbin.org/post",
    data={"username": "samuel", "password": "secret"}
)
# Sets Content-Type: application/x-www-form-urlencoded
⚠️ json= vs data=

Use json= for modern REST APIs — they expect application/json.
Use data= for form submissions and older APIs.
The API documentation will tell you which one.

9.4 Reading the POST Response

Most APIs return the newly created resource in the response body, along with a 201 status code:

response = requests.post(url, json=new_post)

print(response.status_code)  # 201
created = response.json()
print(created["id"])          # the server-assigned ID
📝 Exercises
Exercise 1 — What does json=data do that data=data doesn't?
  • A Nothing — they're identical
  • B Serializes the dict to JSON and sets Content-Type: application/json
  • C Sends the data as a URL query string
json= converts your Python dict to a JSON string and sets the correct Content-Type header. data= sends form-encoded data, which most modern APIs don't expect.
Exercise 2 — What status code typically indicates a resource was successfully created?
  • A 200
  • B 204
  • C 201
201 Created is the standard response for a successful POST that created a new resource. 200 is a generic success. 204 means success with no content to return.
🧠 Try It

Create a new post on JSONPlaceholder. Print the returned id and title. Then try creating one with a missing required field and see what status code you get.

import requests

post_data = {
    "title": "Learning Python APIs",
    "body": "POST requests send data to the server.",
    "userId": 1,
}

response = requests.post(
    "https://jsonplaceholder.typicode.com/posts",
    json=post_data
)

print(f"Status: {response.status_code}")
result = response.json()
print(f"Created post #{result['id']}: {result['title']}")
